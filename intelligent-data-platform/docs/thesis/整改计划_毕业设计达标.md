### 1.1 数据源选型（已核实可获取性）

**交易域（订单 / 支付 / 退货 / 商品 / 用户）→ UCI Online Retail II**

| 项 | 内容 |
| --- | --- |
| 规模 | **1,067,371 行**真实交易，2009-12-01 ~ 2011-12-09 |
| 来源 | UK 注册的线上零售商（主要卖礼品，客户多为批发商） |
| 字段 | `InvoiceNo`（C 开头＝取消）、`StockCode`、`Description`、`Quantity`（负数＝退货）、`InvoiceDate`、`UnitPrice`（英镑）、`CustomerID`、`Country` |
| 授权 | **CC BY 4.0**（署名即可商用/学术使用） |
| 下载 | **免登录直下**：`https://archive.ics.uci.edu/static/public/502/online+retail+ii.zip`（43.5 MB） |
| 引用 | Chen, D. (2012). Online Retail II [Dataset]. UCI ML Repository. `https://doi.org/10.24432/C5CG6D` |
| 适配度 | ★★★★☆ 订单/金额/退货/商品/用户全有；**缺支付状态**（无"支付失败"事件） |

**流量域（浏览 / 点击 / 加购 / 收藏 / 购买 行为）→ 二选一**

| 候选 | 规模 | 授权 | 获取 | 适配度 |
| --- | --- | --- | --- | --- |
| **淘宝用户行为 UserBehavior**（天池 649） | 1 亿行（可抽样） | 天池学术使用条款 | 需阿里账号登录 | ★★★★★ 字段正是 pv/cart/fav/buy + 时间戳 |
| Retail Rocket | 275 万事件 | Kaggle 条款 | 需 Kaggle 账号 | ★★★★☆ view/addtocart/transaction |

> **建议**：交易域用 UCI（免登录、CC BY 4.0，最稳），流量域用淘宝 UserBehavior（字段最贴）。
> 若你无法注册，退路是 Retail Rocket。

### 1.2 字段映射设计（交易域）

| 目标表 | 源字段 → 目标字段 | 处理规则 |
| --- | --- | --- |
| `mysql.orders` | `InvoiceNo` → `order_id`；`InvoiceDate` → `created_at`；`CustomerID` → `user_id` | 一行订单明细聚合为一张订单 |
| `mysql.order_items` | `StockCode` → `product_id`；`Quantity` → `quantity`；`UnitPrice` → `unit_price` | 保留明细粒度 |
| `mysql.products` | `StockCode` → `product_id`；`Description` → `name`；`UnitPrice` 众数 → `price` | 去重取代表值 |
| `mysql.users` | `CustomerID` → `user_id`；`Country` → `region` | 空 CustomerID 的行需处置（约 25%，见风险 R2） |
| `mysql.payments` | 由订单派生：`amount = Σ(Quantity×UnitPrice)`，`status = success` | **无真实支付失败**（见风险 R1） |
| `mysql.refunds` | `InvoiceNo` 以 `C` 开头且 `Quantity<0` → 退货单 | 真实退货，可算退款率 |

### 1.3 必须提前决策的风险

| # | 风险 | 影响 | 处置方案 |
| --- | --- | --- | --- |
| **R1** | 真实数据**没有"支付失败"事件** | 判据 `payment_fail_cnt` 恒为 0，`payment_success_rate` 恒 100% | ①从判据里移除该列并说明；②或改用"取消订单/缺货"当失败（要写清口径） |
| **R2** | Online Retail II 有约 **25% 行 CustomerID 为空** | 无法归属用户，`order_user_cnt` 会偏小 | 丢弃匿名行并在论文说明样本量变化（这是真实数据的正常处理，可写进数据质量章节） |
| **R3** | 数据时间范围是 **2009–2011**，与"实时链路"演示冲突 | 看板"最新窗口"会是 2011 年 | **时间平移**：整体映射到最近 30 天（保留相对间隔），论文里作为方法写明"为演示实时性做时间归一到近 30 天" |
| **R4** | 交易域与流量域**用户不重合** | `ods_user` 无法同时覆盖两域；质量校验"user_id 均存在于 ods_user"会失败 | ①建两套维表（`dim_user_trade` / `dim_user_traffic`）；②或 user_id 加域前缀；③质量校验按域拆开 |
| **R5** | 真实数据有**退货、负数量、零单价、重复发票** | 现有质量校验 25 条可能大面积失败 | 这正是加分项：**把清洗规则写成数据质量章节**，失败项如实列出 |
