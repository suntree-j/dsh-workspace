## 八、可复现性

- 交易域：`python scripts/real-data/build_uci_dataset.py`（窗口 `2009-12-01` ~ `2011-12-10`），
  输出 `user/product/orders/payment/refund` 五个 CSV，`quantity×price == amount` 776,575/776,575 精确相等。
- 流量域：`python .tmp/realdata/tianchi_sample.py`（`N_USERS=100000`、`WIN_LO=1511539200`、`WIN_HI=1512316800`）
  → `traffic_events.csv`；再 `python scripts/real-data/build_tianchi_dataset.py` → 三个 CSV（商品按主导类目去重）。
- 装载：`python -m src.load_real_data --dir data/real --step all`（MySQL 装载 + Kafka 发布，流量域按 10 万条分块）。
- 全链路：`bash scripts/batch-mode.sh`（自动暂停/恢复实时链路）。

## 九、必须如实写明的限制

1. 两域**不是同一个业务**：用户、商品、时间、国家全不重叠，结论是"同一套湖仓与对账方法在两个形态不同的域上成立"，不是"跨域关联分析"。
2. UCI **无类目字段**，11 个类目由商品描述关键词派生，属于派生口径而非原始事实。
3. UCI **约 22.8% 的行没有 Customer ID**，这些行不进入 `orders`（`user_id` 非空约束），已计入清洗漏斗。
4. UCI **退款无法与原始订单按发票号关联**（C 前缀发票与普通发票号匹配率 0/8,292），退款按 `(user_id, product_id)` 的窗口内最早订单关联。
5. 天池**无金额、无订单号、无 CLICK 事件**，因此流量域只贡献行为漏斗，支付失败笔数恒为 0。
6. 两个数据集的类目命名体系不同（中英文、粒度不同），`dim_product` 里并存，未做映射。
7. 时间戳保留原始事件时间（2009–2011 / 2017），未做时间平移；页面上"最新窗口"显示的是数据时间而非当前时间。
