## 三、三个必须提前背准的口径（现场最容易被抓）

### 1. 窗口数：`11458` / `19643` —— 照念即可

对账覆盖窗口数（论文、服务看板、对账汇总表、对账明细表**四方一致**）。

两侧**源表**各多 2 行（`11459` / `19644`），因为对账判据只在**两端都已封窗**的窗口上成立
（`reconcile_batch_realtime.py:36` 的 `TAIL_GUARD_MINUTES = 3`，论文 5.3 节已写明）。

> 若评委对着源表 `COUNT(*)` 问"怎么是 11459"，答：
> **"源表含最近 2 个刚写入、尚未确认封窗的窗口；对账判据只比对两端都已封闭的窗口，
> 所以覆盖 11458 个。两侧都是 11458、单边 0 比 0、不一致 0、GMV 精确到分相等。"**
>
> **不要**说成"时点漂移"、"差 1 是正常的" —— 那是错误解释。

### 2. 判据构成：交易域 **7 个可加 + 1 个去重**

`order_user_cnt` 是唯一去重指标（两侧同为近似去重），**不是"8 个可加"**（论文 5.3 节已订正）。

### 3. 判别力边界：`5504 / 5954`

11458 个窗口中，**5504 个（48.03%）两侧 GMV 均为 0**，属**平凡一致**，不构成独立证据；
真正承载判别力的是 **5954 个有业务量的窗口**。

> 被问"11458 个窗口全验过了？"答"**5954 个有业务量的窗口逐窗口一致；另有 5504 个两侧均为 0，
> 是平凡一致，我不把它算作独立证据。**" —— 主动交底比被戳穿好。

## 四、现场注意事项

| 项 | 说明 |
| --- | --- |
| **演示不要挂 VPN / 代理** | 站点是明文 HTTP（`http://36.151.150.140/data/`，未启用 443）。挂代理时公网访问曾出现**间歇 502**，属链路问题非服务端问题（服务端本机全部 200） |
| 备用方案 | 若现场打不开，改用 `ui-audit-screenshots/after/` 里的截图（10 张，1920 与 1440 两档） |
| 只报有出处的数字 | 每个数字都能在 `EVIDENCE_MATRIX.md` 或 `docs/sprint/SPRINT_*.md` 查到；查不到的**就说"未采集"**，不要估 |
| 禁用词 | 不写、不说：完全一致 / 零差异 / 全量验证 / 生产可用 / 高并发 / 向量 RAG / 真实业务数据 / 完全无损 / 零丢失 |
| 主动交底优先 | 已知缺陷（实时侧 1 个窗口 `click_rate`、批量装载曾清空表、公网间歇 502）**自己先说**，比被问出来强 |
