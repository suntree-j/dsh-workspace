# E05 智能体路径：能力边界与措辞可反查

> 证据台账编号 E05（见 `docs/thesis/REPORT_DRAFT` 的交接包 02 节）。
> 采集时间：2026-11-16 05:39–05:52（Asia/Shanghai）。环境：`http://36.151.150.140/data/agent/`，`engine=langgraph`，`model=deepseek-flash`。

## 一、定位

**现象一（越界 + 无关取数）**：问「帮我写一首关于数据平台的诗歌」时，智能体照写，并且为了给诗配"真实锚点"，额外执行了一条与问题无关的查询
（`SELECT batch_id, compared_at, … FROM lakehouse_ads.ads_reconcile_traffic_summary`），
把真实批次号 `reconcile_traffic_20261116_033826`、区间 `2017-11-25 ~ 2017-12-03`、窗口数 12,957 写进诗里。

性质：越界本身不是数据错误，但它破坏了一条更重要的性质 ——
**「回答里出现的每个数字都来自为这个问题执行过的查询」**。写诗不需要取数，一旦取数，数字就变成装饰品。

**现象二（措辞绝对化）**：同一个问题改问对账，回答写「GMV **完全对得上**，逐分钟窗口没有任何差异」「**完全一致**的窗口数 40,358」。
一次比对能说的只有"我比了 40,358 个窗口，其中 0 个不等"；"完全一致"是对两套系统的绝对保证，不是一次比对能给出的事实。

**代码入口**：
- `services/agent/app/graph.py` 的 `GraphAgent.ask()`：`retrieve → plan → execute → validate → reflect → summarize` 六节点，回答由模型在 `summarize` 节点写出；
- `services/agent/app/graph.py:821` 的 `_graph_system_prompt()`：唯一能约束模型措辞的地方；
- `services/agent/app/scope.py`（本轮新增）：确定性前置判定。

**可重现性**：稳定复现（同一问题连续两次都触发）。响应字段在 `data.data` 下：`answer / executed_sql / graph / model / retries / steps / validation`。

## 二、改动

| 文件 | 改动 | 为什么 |
|---|---|---|
| `services/agent/app/scope.py`（新增） | `_NON_DATA_PATTERNS` 五类模式（creative / translate / chitchat / identity / weather）、`REFUSAL` 固定拒答文案、`classify_question_scope(question) -> ScopeVerdict(verdict, reason, refusal)`；**默认放行** | 把"越界"与"取数"彻底分开：越界时一条 SQL 都不执行 |
| 同上 | `normalize_answer_wording(answer) -> (text, hit)`：把「完全一致 / 完全对得上 / 零差异 / 没有任何差异 / 一模一样 / 毫无差异」换成「逐个相等 / 对得上 / 差异为 0 / 不一致为 0」 | 措辞是结论的一部分；绝对化表述必须换成可被数字反查的说法 |
| `services/agent/app/graph.py` | `ask()` 开头调用边界判定，越界直接返回 `model="scope-guard"`、`executed_sql=[]`、`graph_trace=[{"node":"scope",…}]`；结尾对 `answer` 做 `normalize_answer_wording`，命中时在 trace 追加 `{"node":"wording","replaced":[…]}` | 前者让越界不取数；后者让"这句话被改写过"本身也可复核 |
| `services/agent/app/graph.py:821` | `_graph_system_prompt()` 追加一段措辞约束：对账结论用「不一致窗口为 0 / 差异为 0」，不写「完全一致 / 零差异 / 没有任何差异」 | 提示词是第一道；确定性后处理是第二道 |

**兼容与边界**：
- 只**新增**字段（`graph.trace` 里多一条 node），不删不改既有字段，前端与 MCP 消费方无需改动；
- 边界判定**只挡明确的创作/闲聊**，`代码 / 脚本 / SQL` 不算创作模式，所以「帮我写一段 SQL 查 GMV」照常放行；
- 措辞替换**只换词、不动数字**（有单测钉住这条）。

## 六、MCP 取数路径：可选实现 / 本次实际路径 / 已做的对照

交接包 02 节要求把这三件事分开写，否则论文容易被读成"平台用了 MCP"或"平台没做 MCP"。以下是分别取证的结果。

**1）本次实际路径 = 直连 HTTP**
- 线上 `.env` 只有 `DATA_API_BASE=http://127.0.0.1:8000`（第 245 行），**没有** `AGENT_DATA_PATH`；
- `services/agent/app/config.py:148` 的 `data_path` 默认值即 `http`，且代码把"能连 MCP 就用 MCP"明确排除（自动降级会让"这一次到底走了哪条路"无法断言）；
- 因此上面第一节三条探针跑的**全部是 HTTP 路径**：`ToolBox` → `urllib` → `POST /data/api/query`。

**2）可选实现 = MCP（已部署、已逐一验证可用）**
服务器地址 `127.0.0.1:8200/mcp`（`data-platform-mcp` 单元，`.venv-agent/bin/python -m app.main --transport streamable-http`）。以 `mcp 2.2.0` 客户端 `initialize` + `list_tools` 实测：

| 项 | 结果 |
|---|---|
| 服务标识 | `data-platform-readonly-mcp`，version `1.0.0` |
| 工具数 | **4**：`metrics_lookup`（指标口径字典，唯一权威 `sql/metadata/metrics.md`）、`tables_lookup`（表结构与分层，只含授权表）、`sql_query`（只读 SELECT，经 SQL 守卫与只读账号）、`reconciliation`（批流对账结论） |
| `metrics_lookup("gmv")` | `ok=true`、`found=true`、`source_document=sql/metadata/metrics.md`、`version=V1.2`，返回 2,031 字符 |
| `tables_lookup("trade")` | `ok=true`、`found=true`，返回 31,814 字符 |
| `reconciliation()` | `ok=true`，返回 1,033 字符 |
| `sql_query(SELECT SUM(gmv) … ads_batch_trade_1m)` | `ok=true`、`row_count=1`、`rows=[{"g":"17068016.12"}]`（与批层 GMV 一致） |
| `sql_query(… ecommerce.ods_orders)` | **`ok=false`、`code=TABLE_NOT_ALLOWED`**、`detail="未授权：ods_orders；允许的表见 sqlguard.ALLOWED_TABLES"` |

最后一行是本节最关键的证据：**SQL 守卫在 MCP 这条路上同样生效**，不是只有 HTTP 入口才拦。守卫、只读账号、可访问表清单三条约束对两条路径完全一致，差别只在"谁来发起这次 HTTP"。

**3）已做过的对照（不是本轮新做）**
- 两条路径的终点相同：`POST /data/api/query` + `sqlguard` + `agent_ro` 只读账号；
- `services/agent/app/tools.py:72` 把经 MCP 的工具限定为 `_MCP_TOOL_NAMES = {metrics_lookup, tables_lookup, sql_query, reconciliation}`，`retrieve_docs`、`propose_sql` 始终走本地，不经 MCP——即"能力面可枚举"只覆盖取数四件事；
- `services/agent/app/mcp_client.py` 用**后台守护线程持有长连接**（而不是每次 `asyncio.run` 重新握手），MCP 不可用时**不静默回退 HTTP**（`AGENTS.md` §10.3「失败即失败」）。

**4）本轮未做的事（必须写明，否则等于夸大）**
- **没有**把线上 `AGENT_DATA_PATH` 切成 `mcp` 再端到端跑一遍问答；切换是显式开关（改 `.env` + `systemctl restart data-platform-agent`），但切换本身会改变演示环境的取数路径，故留到需要时再执行；
- 上面的 MCP 证据是"以独立客户端直连 MCP 服务"取得的，证明的是**能力面与守卫**，不是"Agent 经 MCP 的完整问答链路"。

**5）论文写法（第 5 章 / 第 6 章 E05）**
- 写"平台提供两条取数路径，本次部署实际使用直连只读服务；MCP 作为可替换实现已部署并通过工具枚举与守卫验证"，**不要**写成"Agent 通过 MCP 取数"；
- 若答辩被问"MCP 到底有没有用上"，正确回答是：本轮未切换，切换是显式的；MCP 的价值在于**能力面可枚举**（客户端能 `list_tools()` 读出它能做的全部事情并交给安全审查），而不是"多一跳"。
