# ============================================================
# 数据问答 Agent（services/agent）依赖
# ============================================================
#
# 装六样东西：
#   fastapi / uvicorn       对外接口（与数据服务同一套，便于统一部署）
#   openai                  DeepSeek 提供 OpenAI 兼容接口，官方 Tool Calls
#                           示例就是用这个 SDK；不自己拼 HTTP，
#                           少一类边界情况的出错机会
#   httpx                   openai SDK 的传输层依赖（显式声明，避免隐式拉取）
#   langgraph               Sprint 8 的图式编排（规划→取数→校验→反思→汇总）
#   mcp                     Sprint 10 的取数客户端（streamable-http / stdio）
#
# 版本用区间约束而不是 latest：允许小版本浮动，但必须可复现。
#
# ------------------------------------------------------------
# Sprint 8：为什么在此刻引入 langgraph（而 Sprint 7 没有）
# ------------------------------------------------------------
#   Sprint 7 的目标是"自然语言转 SQL 的基础能力"，一个带工具调用的循环就够了；
#   当时引入图会让"这一轮调了什么工具"被状态机掩盖，不利于当时的可验证性。
#   Sprint 8 要的恰恰是**显式的规划、独立的校验、可计数的重试** ——
#   这三件事在自由循环里没有落点，图才有。
#
#   钉 1.1.0（服务器实测可用版本列表含该版本；1.2.x 不用）：
#     langgraph==1.1.0
#
# ------------------------------------------------------------
# Sprint 9：检索**不引入任何新依赖**
# ------------------------------------------------------------
#   检索为词法后端（BM25 + 显式同义词表），纯标准库实现。
#   不引入向量库（Milvus / FAISS / Elasticsearch）的原因见
#   docs/DECISIONS.md ⏳7 与 docs/sprint/SPRINT_9.md 第 2 节：
#   DeepSeek 官方 API 没有 embeddings 端点，本机也放不下本地 embedding 模型。
#
# ------------------------------------------------------------
# Sprint 10：mcp（Agent 侧只用它的客户端角色）
# ------------------------------------------------------------
#   官方 `mcp` SDK 同时是服务器与客户端；Agent 用的是 `Client`
#   （`from mcp import Client`，URL 即 streamable-http，参数对象即 stdio）。
#   为什么不自己按协议拼 JSON-RPC：MCP 的初始化握手、协议版本协商、
#   会话 ID 与事件流语义都属于"自己实现必然出错"的部分。
#
#   版本与 `services/mcp/requirements.txt` **必须一致**：
#   服务端与客户端是同一个包的两个角色，版本不同会出现
#   "协议版本对不上"这种握手期就失败的故障（比运行期失败更难定位）。
#   钉法与版本查证依据见 services/mcp/requirements.txt 顶部说明。
# ============================================================
